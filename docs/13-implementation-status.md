### 2.3 检索与时间版本

- 仅检索每个资源的当前版本，不把历史规定混入当前回答。
- SQLite FTS5 trigram 索引覆盖全部文档版本；每个独立 query 用 BM25 检索，
  标题权重 5、正文权重 1，默认返回 Top 8。
- 二进制原件、待转录图片和待 OCR PDF 不进入事实证据。FTS 返回的短片段只负责
  发现候选材料，不被当作“已经读完整份材料”。
- 已删除培养方案专用查询扩展、年级别名、课程表摘录优先、专升本降权和证据表格
  优先等规则。模型给出的 query 原样进入通用检索；选哪份材料、查找什么表达、
  翻到哪一页以及是否继续阅读都由模型根据问题和真实工具结果决定。
- 每份当前文档可由四个通用原子动作继续探索：`inspect` 返回页/固定文本块目录，
  `find` 返回精确命中和短定位上下文，`read locator` 像翻书一样读取一个完整页/
  文本块，`read segment` 从指定 offset 读取连续小段。它们统一适用于 PDF、HTML
  通知、新闻和其他已解析材料，不包含业务分类器。
- PDF 页级读取在完整连续原文之外提供通用 `[cNNN]` 行列坐标视图，只说明文本
  片段的横向起点，不预先识别表头、行、列或业务语义；横向表格的对应关系仍由
  模型推演。连续段单次预算为 1,000—12,000 字，避免无依据地整份灌入长文档。
- 当前版本、启用来源、Public/Campus 可见性、质量状态和 2023 时间边界通过关系
  查询统一过滤；本地工具不再暴露 `queries`、`source_ids` 或语义软过滤器。
- chunks、384 维本地领域子词向量和结构化实体暂时保留，但不参与主检索。
- 所有历史版本均可重建分块与实体，并支持任意历史版本对比。
- 实时证据只能回写登记来源，并关联可验证的文档版本。

### 2.4 模型原生语义与动态调查

- `SemanticDossier` 由模型生成目标假设、领域、意图、新鲜度、任务形态、实体、
  不确定性和所需证据；分类信号只指导调查，不选择固定回答流程。
- 模糊问题由模型结合原问题、最近对话和确认画像解释；复合问题按独立证据需求
  拆分，不强制用户逐项填写表单或先回答机械澄清问题。
- 调查计划只能从运行时工具目录选择工具；独立步骤并行，有依赖的步骤顺序执行。
- 每个任务有工具调用预算和最多三轮调查；首轮后由模型判断证据充分性，并只补查
  尚未覆盖的关键事实。
- 初始上下文没有 `document_version_id` 时，模型只能先搜索候选；得到真实 ID 后，
  可按“搜索 → 检查/查找 → 按页或块翻阅”的人类式路径继续。协调器只校验 ID、
  locator、offset 和调用预算等原子契约，不替模型判断材料主题或重要性。
- `live_required` 问题若规划器遗漏实时工具，协调器会补入已登记的实时核验工具。
- 官网搜索采用主题相关性优先、官方搜索顺序兜底，不再按发布日期把无关新页面
  排到前面。
- 校园实时检索把来源标签和分类信号降为软排序：每批 3 个来源读取候选，候选得分
  只决定顺序，不能阻止页面读取或正文进入证据池；证据不足时由 Agent 改写短查询
  并继续调查。
- Source Registry 的精确主机、权威单位和访问路由仍是边界；栏目详情正则改为
  归属与解析提示，同一可信主机新增栏目或旧 CMS 的 `permissionread` 页面不会
  因未预登记具体路径而消失。
- 实时工具把已尝试来源、发现候选数和实际读取候选数交给复核器和回答器；
  `exhausted=true` 只表示遍历当前登记入口，不等于读完站内所有页面，任何零命中
  都不能直接写成“学校没有”。
- 明确给出可信校园 URL 时优先直读该页；普通模糊查询仍由模型保留原词并交给
  扩搜器。实时证据先用于当前回答，数据库和索引回写在后台完成。
- 校园记忆把学院和专业作为个性化排序信号；校级国创、校历、学生手册和奖学金
  规则不会因用户画像被硬过滤掉。
- 对正文主要存在于图片中的官方页面，Headless Edge 会捕获正文图片，再由配置的
  多模态模型忠实读取日期与事项；2026—2027 学年校历已用该路径完成真实验收。
- 最终证据按原问题和实际工具查询重排并限量，回答中的校园事实使用可直接打开的
  官方链接。

### 2.5 CA、校内直连与校外 VPN

- 普通校园登录采用 CAS Redirect 与一次性 Service Ticket；应用不接触密码。
- 服务节点能访问校园网时，对登记通知源执行受限的直接只读查询。
- 校外时，用户凭据只在一次性 API→Windows sidecar→Edge 登录链路中出现。
- sidecar 使用系统 Microsoft Edge 的 Headless 模式和本机 aTrust，不依赖 Chrome。
- 中心 API 只保存短时不透明句柄；Cookie、Ticket 和 VPN Token 留在临时
  Edge Context，退出或过期即销毁。
- 37 条已验证 VPN 路由按 Source Registry 映射回登记来源。
- 唯一能力为 `campus_notice.read`。模型只能传 `query` 和 `limit`；问题中若
  已有 URL，只能直读已登记精确主机上的内容页，不能指定任意目标、方法、Header、
  表单或目标学号。
- 业务端点只允许 `GET/HEAD/OPTIONS`；POST 精确限制在 CA 登录、aTrust 会话交换
  和资源目录控制路径；`PUT/PATCH/DELETE` 全部阻断。
- 个人成绩、课表、学分、选课状态、待办和所有申请代办均不在能力范围。
