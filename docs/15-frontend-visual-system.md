# 城知前端视觉系统与参考站审计

版本：v0.1

审计日期：2026-07-26

参考站：[《明日方舟：终末地》官方网站](https://endfield.hypergryph.com/)

## 1. 审计目的

本次审计用于学习参考站的版式组织、信息层级、交互节奏和响应式方法，并将这些规律转译为“城知”校园 Agent 自己的产品语言。

不复制参考站的角色、插画、Logo、专有图标、品牌字体、文案或具体页面构图。城知只复用抽象设计原则，并使用项目自己的内容、CSS 图形和通用开源图标。

## 3. 参考站真正有效的设计语言

### 3.1 不是“黄黑配色”，而是高密度信息与大留白的交替

参考站用两种节奏制造张力：

- 大幅媒介画面、超大标题或纯色块承担情绪；
- 微型编号、英文代号、时间、分类和刻度承担系统感。

内容不会平均塞进许多同质卡片。每个章节有一个明确主角，次要信息依附在边缘、刻度、标签或侧轨上。

### 3.2 工程制图式空间

反复出现的视觉语法包括：

- 细线网格、定位十字和等高线；
- 标尺、序号、坐标、分页数字；
- 裁切边、装配图、技术注释；
- 垂直侧轨和固定工具栏；
- 图像越界、文字压线和不对称构图。

这些元素不是装饰堆叠，而是在持续暗示“这是一个正在运行的系统”。

### 3.3 色彩承担状态，而不是铺满所有容器

基础色为近黑、白和冷灰。高亮黄只用于：

- 当前章节或选中状态；
- 主要行动入口；
- 模块起止边界；
- 少量定位标记。

青、洋红和红只以短线、微型标尺或媒介内容中的局部色出现，不与高亮黄竞争。

城知采用自己的信号色：

- `SIGNAL YELLOW`：主操作、当前状态、正在核验；
- `INK`：正文、强边界、可信结构；
- `PAPER`：阅读面；
- `CYAN`：实时数据与正常通道；
- `MAGENTA`：分类或观察标记；
- `RED`：错误和高风险提醒。

### 3.4 字体通过宽窄反差建立技术感

参考站混合使用：

- 粗重、略窄的主标题；
- 宽体或等宽英文编号；
- 极小字号的系统注释；
- 常规中文正文。

城知不复制参考站品牌字体，改用系统字体组合：

- 中文标题：`Microsoft YaHei UI` / `PingFang SC` 的粗重字重；
- 英文代号：`Arial Narrow` / `Bahnschrift SemiCondensed`；
- 元数据：系统等宽字体；
- 正文：系统无衬线字体。

### 3.5 控件是硬边、明确、可操作的

- 主要按钮采用黑底或黄底的强对比矩形；
- 小型翻页可使用圆形，但不会把所有文字按钮做成胶囊；
- 筛选器像设备控制条，而不是柔软的消费级标签；
- 悬停反馈以位移、反色、短线增长为主；
- 阴影很少，层级主要依靠色块、边框和错位。

### 3.6 动效服务于章节切换

主要动效模式：

- 首屏加载与内容显现；
- 滚动时章节进入、固定导航激活；
- 轮播图像与文字分层切换；
- 控件悬停时短距离位移或反色；
- 少量扫描、记录和刻度动画。

城知首版只迁移轻量动效：

- 页面入场；
- 来源条目错峰出现；
- 核验进度扫描线；
- 主按钮和列表项的 2–4px 位移；
- 尊重 `prefers-reduced-motion`。

## 4. 城知的转译原则

### 4.1 产品隐喻

城知不是游戏资料站，也不是校园公告门户。产品隐喻定义为：

> 一座面向学生开放的“校园信息观测与决策终端”。

因此界面中的工程语言应表达：

- Agent 正在理解问题；
- 信息通道是否在线；
- 当前查了哪些来源；
- 证据版本与观察时间；
- 哪些是事实，哪些是建议；
- 下一步能做什么。

### 4.2 主问答页映射

| 参考规律 | 城知实现 |
|---|---|
| 固定导航侧轨 | 左侧任务说明轨与顶部系统栏 |
| 大主视觉 | “把校园，说清楚”任务宣言 |
| 章节编号 | 理解、调查、证据、回答的编号与进度 |
| 媒介主角 | 当前问题和当前回答成为视觉主角 |
| 资料侧栏 | 右侧 `Evidence Desk` |
| 强行动按钮 | 黄色发送控制与黑色问题入口 |
| 微型技术信息 | 模型状态、来源数量、置信度、核验模式 |

### 4.3 来源观测页映射

| 参考规律 | 城知实现 |
|---|---|
| 角色/资讯索引网格 | 来源目录与资源版本列表 |
| 分类筛选条 | 来源状态和主机白名单 |
| 详情页大信息面 | 选中来源的连接器、周期、版本和资源 |
| 版本日历 | 资源观察时间与版本累计 |
| 新闻元数据 | 发布者、发布时间、观察时间和官方入口 |

### 4.4 响应式策略

桌面端：

- 顶部系统栏保持固定语义；
- 左侧说明轨、中央对话、右侧证据桌形成三栏；
- 中央对话承担主要滚动；
- 证据桌可以独立滚动并保持可见。

移动端：

- 固定侧轨改为紧凑顶部栏；
- 三栏改为单列，但不丢失来源与核验状态；
- 大标题、编号和高亮色保留；
- 网格由多列变为单列或双列；
- 所有操作保持至少 44px 的触控高度；
- 长文正文优先保证字号、行高和连续阅读。

## 5. 明确不做的事情

- 不使用参考站的图片、Logo、角色、装配图或专有字体；
- 不照搬其具体页面比例和模块顺序；
- 不把所有容器做成卡片；
- 不用大面积霓虹、玻璃拟态或发光效果冒充“科技感”；
- 不牺牲正文可读性来追求展示性；
- 不让视觉阶段条变成 Agent 的业务状态机；
- 不隐藏证据、时效和失败状态。

## 6. 验收标准

- 问答页和来源页共享同一套颜色、字体、边框、编号和交互规范；
- 1440px 与 390px 宽度下无横向溢出；
- 键盘焦点清晰，文本对比度满足可读要求；
- `prefers-reduced-motion` 下关闭非必要动画；
- 不加载参考站任何静态资源；
- 页面仍完整支持提问、SSE 过程展示、证据切换、来源切换和外链访问。
