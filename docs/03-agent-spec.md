## 1. 核心原则

HZCU Campus Agent 遵循 Everything is model：模型负责理解问题、形成假设、选择
材料、决定读取范围、解释内容并生成回答；代码负责提供现实工具和执行通用边界。

正常路径不能退化为：

```text
问题 → 业务分类器 → 固定来源/专用脚本 → 模板答案
```

也不能为某一份培养方案、课程表、通知、新闻或评奖材料增加专用优先级来替模型做
判断。

## 2. 模型获得的上下文

每次任务按需向模型提供：

- 用户原始表达；
- 当前会话中必要的近期消息；
- 用户已经确认且与问题有关的画像；
- 当前日期和可用身份范围；
- 运行时实际可用的工具目录；
- 本轮已经取得的工具结果与证据。

原始问题始终保留。语义档案或多假设信号可以帮助模型思考，但不能替代原问题，也
不能在代码中成为业务硬路由。

## 3. 调查过程

```text
理解问题
→ 形成一个或多个可修正假设
→ 选择当前可用的通用工具
→ 搜索候选材料
→ 按需检查结构、文内查找、逐页/块翻阅或读取连续段
→ 判断证据是否足够
→ 必要时改写查询或使用可用实时工具
→ 形成带来源的回答
```

模型决定各步骤的业务意义。Coordinator 只处理步骤依赖、并行执行、调用预算、
参数契约和工具结果回传。

## 4. 类人翻阅的通用原子动作

1. `search_campus_memory`：像查目录一样发现可能相关的材料；
2. `inspect_campus_document`：查看材料有哪些页或文本块；
3. `find_in_campus_document`：在一本材料中寻找模型指定的词或表达；
4. `read_campus_document_locator`：翻到一个完整页/块阅读；
5. `read_campus_document_segment`：从某个位置连续向后阅读；
6. 可用时调用公开或 Campus 实时搜索核对当前信息。

PDF、HTML、扫描 OCR 和其他已解析材料共享这些动作。工具不会预先判断“这是课程
计划”“这是评奖表”或“这一页最重要”；表格行列关系、上下文和取舍由模型理解。

## 5. 证据与回答

- 搜索片段只用于发现候选，不能冒充已经读完原文。
- 校园事实应关联本任务实际取得的证据和可打开来源。
- 模型区分材料明确陈述的事实、基于事实的分析、建议和仍未知的信息。
- 历史材料必须说明适用年级或时间，不能冒充当前规则。
- 多份官方材料冲突时，模型说明差异并优先采用适用范围更明确的当前材料。
- 没有足够证据时透明说明缺口，不把零命中改写成“学校没有”。

引用协议只检查证据 ID、来源和结构关系。语义选择仍由模型完成，不引入关键词分类器
或问题专用筛选器。

## 6. 模糊、多轮与个性化

- 模糊问题允许保留多个合理解释，并先做能够共同帮助这些解释的调查。
- 只有不同解释会明显改变结果且现有材料无法判断时，才向用户提出最小澄清。
- 后续问题可以承接当前会话中的对象、学院、专业和时间范围。
- 只有用户确认的画像可进入上下文；画像只作为模型信息，不过滤本应可见的材料。

## 7. 工具可用性

- 本地镜像搜索在匿名试用模式可覆盖已批准的 Public/Campus 镜像。
- 公开实时工具仅在对应来源和网络可用时提供。
- Campus 实时工具仅在校园身份及路由可用时提供。
- 不可用工具不会以占位形式交给模型，也不会要求模型反复调用。
- 模型无法直接读取数据库、任意文件、任意网络地址或账号凭据。

## 8. 失败处理

- 工具失败时保留已经取得的证据，并把失败原因交回模型。
- 模型输出结构不合约时可做有限重试或透明降级。
- 回答已经持久化后，即使 SSE 中断或页面刷新，用户仍可恢复结果。
- 演示适配器必须明确标识，不得伪装为真实模型语义推理。

## 9. 当前范围规则

- 本文不规划主动提醒、个人教务查询、业务写操作或新的管理功能。
- 测试问题可以用于定位回归，但不能反向生成问题专用规则。
- 新工具、新模型流程和新产品行为必须先由用户确认。
