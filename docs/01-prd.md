# 产品需求：HZCU Campus Agent

| 属性 | 值 |
|---|---|
| 文档编号 | PRD-HZCU-001 |
| 状态 | Current |
| 当前阶段 | 阶段 6：Complete |
| 产品范围决定者 | 用户 |

## 1. 产品目标

建设一个面向浙大城市学院学生的模型原生校园信息 Agent。学生可以用自然语言提出
不完整、口语化或依赖上下文的问题；模型自主搜索已批准的官方校园材料、按需翻阅
文档，并给出带来源、适用时间和下一步建议的回答。

产品不是 FAQ、固定意图客服，也不是用业务脚本替模型决定应该看哪份材料。

## 2. 核心原则

1. Everything is model：理解、材料选择、阅读范围和结论判断交给模型。
2. 工具保持通用和原子：搜索、检查结构、文内查找、按页/块读取、连续段读取。
3. 校园镜像是模型的长期记忆和事实材料，不是业务状态机。
4. 回答校园事实时展示实际来源和适用时间。
5. 面对模糊问题优先调查和回答，仅在结果会明显改变时再追问。
6. 不为单个 PDF、通知、课程表或评奖问题增加专用分类器和硬编码优先级。

## 3. 当前已确认功能

- 中文自然语言与多轮会话。
- 模型自主生成调查步骤并使用校园镜像和已接入的官方读取工具。
- HTML、PDF、扫描材料、图片和办公附件的通用解析/探索。
- 回答中的官方事实、分析建议、不确定性和可点击来源。
- 匿名直接使用 Public 与已批准的 Campus 本地镜像。
- 历史会话、刷新恢复、取消、重试和重新核验。
- 已有的画像确认、待办、反馈和来源账本。
- 桌面与移动 Web。
- 用户明确要求的来源抓取、OCR 和核验材料导入。
- 单机数据库、快照和本地可运行交付。

CA 登录、校园实时查询、VPN sidecar 和只读运营台是已有的可选能力。没有对应环境
配置时，匿名本地镜像版本仍应完整可用。

## 4. 当前数据范围

- 学校主站、信息公开、教务、本科教学、招生和校历。
- 学院通知、工程学院全站及 2023 级以后已抓取的培养方案。
- 创新训练、学科竞赛、科研、讲座和就业信息。
- 学生工作、团学、体育美育、国际交流和校园服务通知。
- 已由用户提供并核验的正式扫描材料。

具体来源以 Source Registry 和当前数据库为准。新增学院、栏目或材料范围必须由用户
明确指定，不由开发者自行扩展。

## 5. 当前不做

- 未经用户提出的新产品功能。
- 个人成绩、课表、学分和申请状态。
- 选课、报名、提交、撤回等业务写操作。
- 主动提醒、订阅和推送。
- 新管理流程、审核流或内容发布系统。
- 为未知生产环境提前建设多实例、容量平台或额外安全工程。
- 为项目自行建立人工标注、独立评审、领导彩排或发布认证流程。

这些内容只有用户明确提出后才能进入需求文档和开发计划。

## 6. 阶段 6 结果

阶段 6 已于 2026-08-11 完成：

1. 已确认功能均已接通或修复；
2. 用户提供的模型配置能够直接运行真实 Agent；
3. Web、API、本地镜像、SQLite 和快照已在当前开发机共同运行；
4. 真实 Edge 已完成匿名提问、来源、历史、反馈、待办和来源账本全流程；
5. API 重启后会话与回答能够恢复。

用户已明确决定暂不进行实际目标机器部署。该工作不是阶段 6 遗留项，未来仅在用户
重新提出后启动。完成记录见
[阶段 6：功能完成与本地可运行交付](20-stage-6-productization.md)。

## 7. 需求变更规则

- 用户提出或确认的功能才能加入本 PRD。
- 开发者、评测文档、历史路线图和测试结果不能自行创建需求。
- 修复现有功能不需要新增 PRD 编号。
- 观察到的性能或质量数据先作为问题信息，不自动变成阈值和门槛。

旧版 PRD 编号和 Release B/C 构想保留在历史记录中时，仅供背景参考，不属于当前
开发范围。
