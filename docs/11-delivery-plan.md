## 1. 执行原则

- 优先完成可运行的产品，不自行增加流程、指标和衍生工程。
- 只实现用户已经确认的功能和用户指定的资料范围。
- 开发中发现的问题按功能缺陷处理，不自动升级为新 PRD、平台或评测体系。
- 性能数据、测试结果和安全检查用于定位真实问题，不自动成为阶段门槛。
- 任何新增功能必须由用户提出或明确确认。
- 保持 Everything is model 与通用原子工具原则，不为单一问题增加业务分类器。

## 3. 阶段 6 完成结果

- 用户提供的模型配置可以通过 `make api-real` 直接加载，不需要复制到 `.env`。
- Web、API、本地镜像、SQLite 和快照在当前开发机共同运行。
- 匿名用户可以查询已批准的 Public/Campus 本地镜像。
- 真实模型问答、来源打开、反馈、历史恢复、待办、来源账本和移动端界面已通过系统
  Microsoft Edge 实测。

- 上游 overload 使用通用有限重试处理，不引入业务专用分类或优先级。
- 后端全量测试、前端类型检查和生产构建通过。
