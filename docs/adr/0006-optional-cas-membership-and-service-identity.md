# ADR-0006：用户校园身份与采集服务身份分离

| 属性 | 值 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-07-26 |

> 2026-07-26 补充：信息中心随后授权校外通知查询的短时凭据交接。该例外及其
> 强制只读边界由 [ADR-0007](0007-campus-notice-read-capability-and-vpn-sidecar.md)
> 定义；本 ADR 的身份分离与“不把学生会话作为后台采集身份”仍然有效。
>
> 2026-07-28 补充：Stage 6 单机 Pilot 可由部署负责人显式批准，将现有 Campus
> 本地镜像整体开放给匿名试用。匿名身份仍是 `public`；该批准只影响本地镜像
> 检索和来源账本，不允许实时 Campus 查询、后台采集、Personal 或 Restricted
> 数据。未确认整份 Campus 镜像适合 Pilot 参与者前必须关闭该开关。

## 背景

阶段 2 新增了仅限校园成员查看的来源。系统同时存在两类身份需求：

1. 学生证明自己是校园成员，以读取 `campus` 可见性的信息；
2. 后台采集器在无人值守的服务器上访问经学校批准的内部来源。

CAS Ticket 与发起登录时的 `service` 精确绑定。学生登录本应用取得的 Ticket 不能
转交给教务、综合门户等其他系统，也不能把学生密码保存下来供采集器重放。

## 决策

- Web 采用可选 CAS 登录。匿名用户始终保留 `public` 范围；CAS 验证成功后增加
  `campus` 范围。
- Stage 6 Pilot 的本地镜像读取是独立的数据发布授权，不写入身份范围，也不传给
  Campus 实时工具。部署开关关闭时仍执行原始 `public` 限制。
- 浏览器将账号和密码直接提交给学校 CA。本应用只接收一次性 Service Ticket，
  服务端验证后签发自身的随机、可撤销会话。
- 本地用户只保存 HMAC 化主体标识和脱敏尾号，不保存学号明文、密码、TGC 或
  CAS Ticket。
- 所有写请求执行双提交 CSRF 校验；对话绑定创建者；任务在创建时固化服务端
  计算的可见性范围。
- 采集器不得借用任何学生会话。需要认证的后台连接器使用学校批准的独立只读
  服务账号、正式 API/OIDC 客户端或短期令牌。
- 服务账号秘密只从 Secret Manager 或受控运行时注入，Cookie、Ticket、Token
  只驻留短期内存或加密会话存储，不进入 Source Registry、日志、快照或模型。
- 生产启用前必须由信息化部门登记精确 HTTPS 回调地址。未登记或仍是 HTTP 的
  浏览器登录入口保持关闭。
- 成绩、个人课表、选课操作、申请状态等 `personal` 能力不因本 ADR 提前进入
  阶段 2，仍需独立委托授权与安全评审。

## 后果

正面：

- 可以在不破坏公开访问的前提下接入校园级信息。
- 学生凭据不会进入应用、模型和采集流水线。
- 登录、检索和对话的权限边界可以被测试和审计。
- 后续接入综合门户时不会形成共享负责人账号的混淆代理。

代价：

- 需要学校登记 CAS Service、提供 HTTPS 入口并确认回调域名。
- 后台内部源需要另外申请服务账号或正式机器接口。
- 登录前后的对话必须隔离，前端需要在权限变化时创建新对话。

## 被否决或推迟的方案

- 让所有学生必须登录后才能问公开问题。
- 保存负责人账号密码并由 Agent 按需登录所有系统。
- 把用户 CAS Ticket 转发给其他业务系统。
- 仅在前端隐藏校园来源而不在检索和资源 API 过滤。
- 在阶段 2 接入个人成绩、课表或代办操作。
