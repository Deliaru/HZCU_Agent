# ADR-0004：首期采用单协调 Agent 与受控工具生态

| 属性 | 值 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-07-25 |

## 背景

系统需要语义理解、实时搜索、政策查询、比较、证据校验和记忆。将每项能力实现为互相对话的独立 Agent 会增加延迟、成本、调试难度和责任不清，尤其不适合初始单人开发与运营。

## 决策

- 使用一个主协调 Agent 保持用户目标和上下文。
- 语义感知、证据评价和抽取可以使用独立模型调用，但它们是受控能力模块，不是拥有独立目标的自治 Agent。
- 外部能力通过有 Schema、权限、预算和审计的工具提供。
- 后台采集 Worker 是确定性服务，不称为对话 Agent。

未来只有在任务隔离、权限隔离或独立并行收益经过数据证明时，才拆分自治 Agent。

## 后果

正面：

- 用户目标在一个上下文中保持一致。
- 工具调用和证据链容易审计。
- 降低模型互相误解与重复搜索。
- 更适合渐进开发。

代价：

- 主协调上下文和 Prompt 需要精心管理。
- 复杂任务的并行由 Planner 与工具层承担。
- 主模型故障影响面较大，需要降级模型。

## 被否决或推迟方案

- 多个业务 Agent 互相对话。
- 每类校园问题一个独立 Agent。
- 无限制的 Agent 群自主协商。
