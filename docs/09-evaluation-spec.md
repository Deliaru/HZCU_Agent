# 功能回归与问题定位参考

| 属性 | 值 |
|---|---|
| 文档编号 | SPEC-EVAL-001 |
| 状态 | Optional Diagnostic Reference |

## 1. 用途

本文件只说明出现实际功能问题时如何复现和定位。它不规定样本数量、准确率阈值、
人工标注、独立评审、性能分桶、浏览器矩阵或发布等级。

## 2. 优先检查真实使用结果

针对用户实际遇到的问题，依次确认：

1. 原问题和必要会话上下文是否完整交给模型；
2. 模型实际选择了哪些通用工具；
3. 本地镜像是否存在候选材料；
4. 模型是否继续检查、查找和翻阅了需要的页或文本块；
5. 最终回答中的来源、适用时间和正文是否对应；
6. 失败发生在模型、工具、网络、解析、API 还是 Web 展示层。

修复应作用于通用能力，不能为某一道问题增加固定答案、专用分类器、固定来源列表或
业务优先级。

## 3. 可复用的现有检查

- API 单元和端到端测试可用于发现代码回归；
- Web typecheck 与 production build 可用于发现构建错误；
- 既有检索问题集可在检索发生实际回归时辅助定位；
- Headless Edge 脚本可在移动 Web 出现实际问题时复现交互；
- 历史性能报告只用于比较同类故障，不自动形成优化任务。

是否运行这些检查由本次改动和实际问题决定，不要求每次全部执行。

## 4. 结果处理

- 功能错误直接修复并记录影响；
- 来源缺失由用户确认是否扩大资料范围；
- 部署错误更新实际命令和配置说明；
- 性能观测先作为故障信息，不自动设立指标工程；
- 测试暴露的新产品想法先交给用户决定，不直接写入 PRD。
