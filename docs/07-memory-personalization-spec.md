# 会话、画像与手动待办

| 属性 | 值 |
|---|---|
| 文档编号 | SPEC-MEM-001 |
| 状态 | Current Implementation Reference |

## 1. 当前范围

本文件只描述已经确认并实现的主体数据功能：历史会话、已确认画像、手动待办和
回答反馈。它不规划主动提醒、订阅、个人教务数据或新的个性化产品。

## 2. 主体与会话

- 匿名首次访问创建随机设备主体，服务端 Cookie 只保存不可猜测的会话标识。
- 会话、消息、任务、回答、画像、待办和反馈均按主体隔离。
- 匿名设备之间不推断关联，不使用浏览器指纹合并数据。
- 刷新后可以恢复历史会话；用户可以改名或删除自己的会话。
- 可选 CA 登录保留原设备上下文。匿名数据是否并入校园身份必须由用户明确确认。

## 3. 模型上下文

Agent 每次只接收完成当前问题所需的内容：

- 当前用户原始问题；
- 当前会话中必要的近期消息；
- 用户已经确认且与问题有关的画像属性；
- 当前时间、身份可用范围和动态工具目录；
- 本轮调查取得的真实证据。

模型可以结合这些信息推理，但代码不能用单一画像标签选择固定业务流程或过滤掉
本应可见的校级材料。

## 4. 画像确认

- 只有用户明确确认的画像属性才能进入后续 Agent 上下文。
- 模型提出的画像建议必须引用本轮用户原文；服务端再次确认该文字确实存在。
- 用户可以接受、拒绝、更正或按字段删除画像。
- 冲突属性不能静默覆盖，应保留为待确认建议。
- 姓名、性别、年龄等与问题无关的敏感属性不得用于推荐。

## 5. 手动待办

- 待办由用户手动新增、完成或删除。
- 待办不会自动发送提醒，不根据通知自动创建，也不执行校园业务操作。
- 待办仅属于当前主体，不能被其他匿名设备读取。

## 6. 回答反馈

用户可以对回答提交反馈。反馈关联当前回答和主体，用于排查实际问题；它不会自动
产生新功能、评测项目或画像属性。

## 7. 当前不包含

- 主动提醒、订阅、邮件或校内消息推送；
- 个人成绩、课表、学分、选课或申请状态；
- 自动报名、提交、撤回、评价或预约；
- 未经用户确认的长期推断画像；
- 新的画像评分、推荐算法或运营流程。

这些能力只有用户明确提出后才能进入 PRD 和开发计划。
